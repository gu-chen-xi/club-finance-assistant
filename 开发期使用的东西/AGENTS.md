# 项目名称：社团财务报账助手（Club Finance Assistant）

## 1. 项目背景与目标
我是一名高校社团财务人员。每次活动结束后，我需要整理大量报账材料（发票、凭证、领取表、验收单、活动策划、非公务卡审批表等），并严格按照学校要求命名文件夹、校验金额、跑签字、先交电子版审核，再交纸质版到指定位置。当前流程全靠手动建文件夹、改文件名、对账，极易出错、漏材料、被退回。
我需要开发一个**本地桌面端软件**，将报账流程流水线化、自动化，解决我的痛点。

## 2. 技术栈要求
- 外壳：Tauri（强烈推荐，轻量）或 Electron。
- 前端：HTML + CSS + JS（建议用 Vue3 或 React + TailwindCSS，方便快速出界面）。
- 数据存储：SQLite（或浏览器 IndexedDB / localStorage 进行本地持久化）。
- 文件存储：图片和 PDF 存本地文件夹，数据库只存**绝对路径**。
- 打包目标：生成 Windows `.exe` 可执行文件。

## 3. 核心功能模块

### 模块一：活动报账流水线（核心页面）
界面采用三栏式布局：
- 左侧：导航栏（工作台、活动报账、总账、报销跟踪、模板库、设置）。
- 中间：活动报账流水线。
- 右侧：报账体检面板（实时显示缺什么、错什么）。

**流水线步骤（每个活动一个实例）：**
1. 活动策划（提示：纸质版要交 2 份，需签字）
2. 采购清单（表格：物品名称、数量、单价、总价，自动计算 总价=数量×单价）
3. 发票（拖拽上传，自动命名：`物品名称+金额.jpg`，禁止 png，只允许 jpg/pdf）
4. 凭证（上传消费截图，自动检查：是否有金额、是否有指导老师公务卡后四位；退款需单独标记）
5. 领取表 / 验收单（领取表命名 `领取表1.jpg`；验收单需电子版+纸质版，自动校验总价=数量×单价）
6. 非公务卡（如适用，上传《非公务卡结算特殊情况审批表》，一式两份；不适用则自动跳过）
7. 生成电子包（一键按规则生成文件夹结构，自动复制、重命名文件）
8. 电子审核（状态：待提交 → 已提交社管财务部 → 审核中 → 通过 / 退回，退回需填原因）
9. 纸质提交（生成纸质清单，勾选后标记“已交到303社管柜子财务部那一格”）
10. 归档（归档到历史，自动更新总账）

**状态颜色规范：**
- 灰=未开始，蓝=进行中，绿=已齐全，红=有问题，紫=已提交，金=已通过，深灰=已归档。

### 模块二：智能文件整理（一键生成报账包）
必须严格按照以下规则生成文件夹结构：
- 第一层：`xx社团打给xx老师xx元`（例：`青年网络思行社打给徐泽梅38.67元`）
- 第二层：
  - `X张发票X元`
  - `X张消费凭证X元`
  - `X张领取表` 或 `验收单`
  - `活动具体名称`
  - `非公务卡结算审批表（如适用）`
- 内部文件命名规则：
  - 发票：`物品名称+具体金额.jpg`
  - 凭证：`消费凭证XX元.jpg`
  - 退款凭证：`退款XX元.jpg`
  - 领取表：`领取表1.jpg`、`领取表2.jpg`
  - 验收单：`纸质验收单1.jpg`、`电子验收单.docx`

### 模块三：报账体检面板（右侧）
永远显示当前活动的材料完整度：
- ✅ 已齐全
- ⚠️ 警告（如：发票命名不规范、凭证缺公务卡后四位）
- ❌ 缺失（如：缺1张发票、缺验收单签字）
- 💡 一键修复命名按钮
点击红色项，跳转到对应上传区。

### 模块四：总账与仪表盘（工作台首页）
- 卡片展示：社团当前余额、本月支出、待报销金额。
- 待办事项：列出所有进行中活动的待办（如：第01次迎新晚会缺1张凭证）。
- 快捷新建活动按钮。
- 图表（ECharts）：饼图（活动支出占比）、柱状图（月度支出趋势）。

### 模块五：模板与设置
- 模板库：用户可自行添加自定义模板（pdf/doc/docx/xlsx），支持打开、导出到桌面、删除。
- 设置项：社团名称、指导老师姓名、老师公务卡后四位、学校税号、默认交表位置（303办公室社管柜子财务部那一格）。

## 4. 关键业务规则（必须硬编码到逻辑中）
1. **发票格式**：仅支持 jpg / pdf，遇到 png 提示转换。
2. **发票抬头**：必须包含“重庆城市职业学院”及正确税号。
3. **凭证要求**：必须有清晰金额 + 指导老师公务卡后四位（尾号）。
4. **领取表**：严格按模板，每页保留表头，不得在表格外空白处手写，纸质交原件。
5. **验收单**：电子版 + 纸质版，总价必须等于 数量×单价，需经办人、验收人、部门负责人签字。
6. **非公务卡**：一式两份，一份交财务处，一份自留。
7. **报账流程**：活动结束 → 整理全部材料 → 生成电子包 → **先交电子版给“社团管理部财务部”审核**（不是学校财务处，不是我自己）→ 审核无误 → 打印纸质版签字 → 交到303办公室社管柜子财务部那一格。
8. **禁止零散交**：必须全部整理好一起交，乱放导致丢失后果自负。

## 5. 数据结构建议（SQLite 表设计）
- `activities` 表：id, name, date, status, budget, actual_cost, folder_path
- `invoices` 表：id, activity_id, item_name, amount, file_path, file_type, is_named_correctly
- `vouchers` 表：id, activity_id, amount, file_path, card_last_four, is_refund
- `receipts` 表：id, activity_id, type (领取表/验收单), file_path, total_price, quantity, unit_price
- `reimbursements` 表：id, activity_id, status (待提交/审核中/退回/已报销), submit_date, reject_reason
- `settings` 表：club_name, teacher_name, card_last_four, tax_number, submit_location

## 6. 开发里程碑建议
- Phase 1：先做“活动报账流水线 + 一键生成报账包 + 报账体检面板”（解决90%痛点）。
- Phase 2：加入总账、图表、导出 Excel。
- Phase 3：加入模板库、自动重命名、备份/恢复功能。
