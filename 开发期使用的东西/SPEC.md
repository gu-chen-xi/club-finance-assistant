## 2. 流水线 10 步规格（M1）

每个活动是一个独立实例，步骤顺序固定，但第 6 步（非公务卡）可跳过。

| 步 | 名称 | 用户动作 | 系统校验 | 进入下一步条件 |
|---|---|---|---|---|
| 1 | 活动策划 | 上传策划书 PDF/图片；记录活动名称、日期 | 活动名非空、日期已选 | 已上传至少 1 个文件 |
| 2 | 采购清单 | 表格录入：物品名称/数量/单价 | 单价>0、数量>0；总价自动=数量×单价 | 至少 1 行，且合计金额>0 |
| 3 | 发票 | 拖拽上传 jpg/pdf（拒绝 png，提示转换） | 扩展名 ∈ {.jpg,.jpeg,.pdf}；发票数量**独立统计**（用于报账包文件夹名），不与凭证/采购行做数量对应 | 至少 1 张发票 |
| 4 | 凭证 | 上传消费截图；标记是否退款 | 手填金额>0；手填公务卡后 4 位（默认读设置，可改）；退款凭证单独标记 | 金额校验：`|凭证支出合计 − 发票合计| ≤ 10 分` 通过；凭证<发票且差>10 分红项阻断；凭证>发票且差>10 分黄项警告 |
| 5 | 领取表/验收单 | 二选一或都要；领取表按张上传；验收单需电子版(.docx)+纸质扫描(.jpg) | 验收单：手填 total=quantity×unit_price，不等则红；签字项勾选 | 按类型齐全 |
| 6 | 非公务卡 | 是/否切换；"是"则上传审批表 jpg/pdf | 文件存在且一式两份（提示，不强制校验数量） | 选择"否"或"是且已上传" |
| 7 | 生成电子包 | 点按钮，选输出目录，按 M2 规则生成 | 所有红项必须清零才能生成；弹进度 | 输出目录存在/可创建 |
| 8 | 电子审核 | 手改状态：待提交→已提交→审核中→通过/退回 | 退回必须填原因；"通过"后才能进下一步 | 状态=通过 |
| 9 | 纸质提交 | 打印清单；逐项勾选"已交到 303" | 勾选项数=清单项数 | 全部勾选 |
| 10 | 归档 | 点归档按钮 | 把活动移到历史；总账累加 actual_cost | 无前置 |

## 3. 硬编码业务规则（不可在前端绕过）

1. **发票格式白名单**：`.jpg / .jpeg / .pdf`。遇到 `.png` 直接拒绝并 toast 提示"请转换为 jpg/pdf 后再上传"。
2. **发票抬头校验**：OCR 暂不做（P1 不做 AI 识别），改为**用户手动勾选"抬头已核对为：重庆城市职业学院 + 税号（设置里维护）"**。未勾选则第 3 步不能变绿。
3. **凭证必填**：金额（数字，>0，单位元，最多两位小数）+ 公务卡后四位（4 位数字）。退款凭证 `is_refund=true`，单独计入"退款金额"而非支出。
4. **验收单金额校验**：`total_price == quantity * unit_price`（浮点用分做整数比较，容差 0.01）。不等则红，不允许进入下一步。
5. **非公务卡**：一式两份（提示文字固定："一份交财务处，一份自留"）。
6. **审核路径**：电子审核对象是"社团管理部财务部"，不是学校财务处，不是自己。UI 文案固定。
7. **纸质提交位置**：默认值 `303 办公室社管柜子财务部那一格`（可在设置里改）。
8. **禁止零散交**：第 7 步生成电子包前，必须所有红项清零；黄项可通过但提示。
9. **金额单位**：全系统用"分"（int）存储，显示时除以 100，避免浮点误差。
10. **发票与凭证金额容差校验**（核心规则）：发票金额合计与凭证**支出**金额合计均按"分"做整数比对，差值 ≤ 10 分（±0.1 元）视为正常通过；差值 > 10 分时：凭证支出 < 发票 → 红项阻断生成；凭证支出 > 发票 → 黄项警告不阻断。**发票张数与凭证张数各自独立统计**（用于报账包文件夹名如 `X张发票X元`、`X张消费凭证X元`），两者之间不做数量对应或抵消。支付平台满减/随机立减造成的几分钱差异属正常范围。
11. **日期**：存 ISO `yyyy-MM-dd`。

## 4. 报账包生成规则（M2）

### 4.1 文件夹树

```
<用户选的输出根目录>/
└── <社团名>打给<老师姓名><总金额>元/        # 第一层，例：青年网络思行社打给徐泽梅38.67元
    ├── <N>张发票<发票总额>元/
    ├── <N>张消费凭证<凭证总额>元/           # 含退款凭证时，文件夹名只算支出凭证
    ├── <N>张领取表/  或  <N>张验收单/
    ├── <活动具体名称>/                      # 放活动策划
    └── 非公务卡结算审批表/                  # 仅第6步选"是"时生成
```

### 4.2 内部文件命名

| 类型 | 命名规则 | 示例 |
|---|---|---|
| 发票 | `<物品名称>+<金额>.jpg` 或 `.pdf` | `矿泉水+38.67.jpg` |
| 凭证（支出） | `消费凭证<金额>.jpg` | `消费凭证12.50.jpg` |
| 凭证（退款） | `退款<金额>.jpg` | `退款5.00.jpg` |
| 领取表 | `领取表<序号>.jpg` | `领取表1.jpg`、`领取表2.jpg` |
| 验收单（纸质） | `纸质验收单<序号>.jpg` | `纸质验收单1.jpg` |
| 验收单（电子） | `电子验收单.docx` | — |
| 活动策划 | `活动策划.pdf` 或保留原扩展名 | — |
| 非公务卡审批表 | `非公务卡结算特殊情况审批表<序号>.pdf` | — |

### 4.3 同名冲突

输出目录已存在同名文件时，追加 `_1`、`_2`…；整个顶层文件夹已存在时，弹窗询问：覆盖 / 另存为带时间戳后缀。

## 6. 数据结构（SQLite，单文件 `app.db`）

> 金额一律用 INTEGER 存"分"（乘以 100 的整数），显示时除以 100。日期存 TEXT `yyyy-MM-dd`。

### 6.1 settings（单行表）

| 字段 | 类型 | 说明 |
|---|---|---|
| club_name | TEXT | 社团名 |
| teacher_name | TEXT | 指导老师姓名 |
| card_last_four | TEXT | 公务卡后四位（4 位数字） |
| school_tax_no | TEXT | 学校税号 |
| submit_location | TEXT | 默认交表位置，默认 `303办公室社管柜子财务部那一格` |
| initial_balance | INTEGER | 初始余额（分），默认 0；**首次启动不弹窗引导**，用户后续在设置里改 |

### 6.2 activities

| 字段 | 类型 | 说明 |
|---|---|---|
| id | TEXT PK | `a-yyyyMMdd-序号` |
| name | TEXT | 活动名 |
| date | TEXT | `yyyy-MM-dd` |
| current_step | INTEGER | 1..10 |
| budget | INTEGER | 预算（分），可空，不强制 |
| actual_cost | INTEGER | 实际花费（分），归档时回填 |
| folder_path | TEXT | 该活动原始材料目录绝对路径 |
| review_status | TEXT | `pending/submitted/reviewing/approved/rejected` |
| review_reject_reason | TEXT | 退回原因 |
| paper_submitted | INTEGER(0/1) | 纸质是否已交 |
| archived | INTEGER(0/1) | 是否已归档 |
| created_at | TEXT | ISO 时间 |

### 6.3 purchase_items
`id, activity_id(FK), name, quantity, unit_price_cent`

### 6.4 invoices
`id, activity_id(FK), item_name, amount_cent, file_path, file_ext, head_checked(0/1)`

### 6.5 vouchers
`id, activity_id(FK), amount_cent, file_path, card_last_four, is_refund(0/1)`

### 6.6 receipts
`id, activity_id(FK), type('receipt'/'acceptance'), file_path, total_price_cent, quantity, unit_price_cent, handler_signed(0/1), acceptor_signed(0/1), leader_signed(0/1)`

### 6.7 non_card
`activity_id(PK,FK), applicable(0/1), files(TEXT 数组 JSON 字符串)`

**约束**：
- `file_path` 存绝对路径，正斜杠。
- 删除活动时**不删文件**，只删 DB 记录（级联删各子表）；UI 提示"文件仍在磁盘"。
- DB 文件路径放在系统 AppData（Tauri `app_data_dir()`），不放安装目录，避免权限问题。

## 7. 异常状态与边界条件（因果对照）

| 触发条件 | 系统表现 | 原因（为什么这么做） |
|---|---|---|
| 上传 png | 拒绝，toast "请转 jpg/pdf" | 学校系统不收 png |
| 发票金额合计 ≠ 采购清单合计 | 黄项警告，不阻断 | 可能有赠品/零头，人工判断 |
| 发票合计 − 凭证支出合计 ∈ [−10, 10] 分 | 通过，显示"✅ 金额校验通过（允许微小支付差额）"；差值 ≠ 0 时附**深绿色**提示"存在 N 分微小差额，请注意核验支付平台满减或抹零" | 满减/随机立减导致几分钱差异，属正常 |
| 凭证支出合计 < 发票金额合计，差值 > 10 分 | 红项，阻断生成 | 凭证不足会被财务退回 |
| 凭证支出合计 > 发票金额合计，差值 > 10 分 | 黄项警告，不阻断 | 金额多出，需人工核验 |
| 发票张数 / 凭证张数 | 各自独立计数展示，不互相抵消 | 文件夹名 `X张发票X元`、`X张消费凭证X元` 依赖独立数量 |
| 验收单 total ≠ qty×price | 红项，阻断 | 公式是学校硬要求 |
| 公务卡后四位 ≠ 设置里的尾号 | 黄项，提示"是否录错" | 可能换了卡 |
| 第 6 步选"否" | 流水线自动跳过 6，进度条不卡住 | 非公务卡不是必填 |
| 第 8 步选"退回"但原因空 | 禁止切换状态 | 退回原因要留档 |
| 第 7 步生成包时存在红项 | 弹窗"尚有 N 项未解决"，不生成 | 禁止带病提交 |
| 输出目录已存在同名顶层文件夹 | 弹窗三选一：覆盖/时间戳另存/取消 | 防止误覆盖旧包 |
| SQLite 文件损坏 | 启动时把 `app.db` 备份为 `app.db.bad.<时间戳>` 并新建空库 | 不让软件起不来 |
| 磁盘空间不足（<100MB 可用） | 生成包前警告 | 大图片复制失败难排查 |
| 设置里社团名/老师名空 | 工作台允许，但生成报账包时红项阻断 | 第一层文件夹名依赖这两个值 |
| 余额 < 50 元（即 <5000 分） | 余额卡片红光闪烁（P2 彩蛋） | 原始需求 |
| 重复打开同一文件 | 上传前算 MD5，同一活动内重复则提示"已存在" | 避免重复报账 |

## 8. 非目标（P1 不做）

- OCR 识别发票/凭证金额（P3 再议）。
- 联网同步、多用户、云备份。
- 自动发送邮件/微信通知。
- 复杂权限（单用户本地工具）。
